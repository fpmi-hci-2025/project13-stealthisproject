# Лабораторная работа №4. Моделирование требований REST API

## 1. Модель требований (Actor → User Story → Use Case)

В таблице ниже представлено отображение потребностей пользователей (User Stories) на функциональные варианты использования системы (Use Cases).

| Актор | User Story (Пользовательская история) | Use Case (Вариант использования) |
| :--- | :--- | :--- |
| **Пассажир** | **US-1.1** Как пассажир, я хочу регистрироваться в системе, чтобы иметь личный кабинет и сохранять свои данные. | **UC-1** Регистрация |
| **Пассажир** | **US-1.2** Как пассажир, я хочу авторизоваться в системе, чтобы получить доступ к истории поездок и сохраненным данным. | **UC-2** Авторизация |
| **Пассажир** | **US-1.3** Как пассажир, я хочу искать ж/д рейсы по станции отправления, прибытия и дате, чтобы найти подходящий поезд. | **UC-3** Поиск рейса |
| **Пассажир** | **US-1.4** Как пассажир, я хочу просматривать детальную информацию о рейсе (остановки, время в пути), чтобы спланировать маршрут. | **UC-4** Просмотр деталей рейса |
| **Пассажир** | **US-1.5** Как пассажир, я хочу видеть визуальную схему вагона и выбирать конкретное место, чтобы ехать с комфортом. | **UC-5** Выбор места на схеме |
| **Пассажир** | **US-1.6** Как пассажир, я хочу оплачивать выбранные билеты онлайн картой, чтобы не стоять в очереди в кассу. | **UC-6** Покупка билета<br>(включает **UC-7** Оплата заказа) |
| **Пассажир** | **US-1.7** Как пассажир, я хочу просматривать историю своих прошлых и предстоящих поездок, чтобы управлять своими планами. | **UC-8** Просмотр истории поездок |
| **Пассажир** | **US-1.8** Как пассажир, я хочу иметь возможность вернуть билет онлайн, если мои планы изменились. | **UC-12** Возврат билета |
| **Администратор** | **US-2.1** Как администратор, я хочу добавлять и редактировать расписание рейсов, чтобы поддерживать актуальность информации. | **UC-9** Управление рейсами |
| **Администратор** | **US-2.2** Как администратор, я хочу просматривать список всех заказов в системе, чтобы анализировать продажи и решать спорные вопросы. | **UC-10** Просмотр всех заказов |
| **Кассир** | **US-3.1** Как кассир, я хочу быстро находить рейсы и оформлять билеты для покупателя на вокзале, чтобы обслуживать очередь максимально быстро. | **UC-11** Продажа билета через кассу<br>(использует **UC-3**, **UC-7**) |

## 2. Реестр вариантов использования (Use Case Registry)

Полный список выявленных вариантов использования для системы продажи ЖД билетов.

| ID | Название | Описание | Актори |
| :--- | :--- | :--- | :--- |
| **UC-1** | **Регистрация** | Создание новой учетной записи пользователя в системе. | Пассажир |
| **UC-2** | **Авторизация** | Вход зарегистрированного пользователя в систему по email и паролю. | Пассажир, Администратор, Кассир |
| **UC-3** | **Поиск рейса** | Поиск доступных поездов по заданным критериям (откуда, куда, дата). | Пассажир, Кассир |
| **UC-4** | **Просмотр деталей рейса** | Получение расширенной информации о маршруте, типе поезда и остановках. | Пассажир |
| **UC-5** | **Выбор места на схеме** | Просмотр схемы вагона (занято/свободно) и выбор места. | Пассажир |
| **UC-6** | **Покупка билета** | Процесс оформления билета, включающий выбор пассажира и инициацию оплаты. | Пассажир |
| **UC-7** | **Оплата заказа** | Проведение финансовой транзакции через платежный шлюз. | Пассажир, Кассир |
| **UC-8** | **Просмотр истории поездок** | Отображение списка купленных билетов текущего пользователя. | Пассажир |
| **UC-9** | **Управление рейсами** | CRUD-операции для сущностей Поезд, Маршрут, Расписание. | Администратор |
| **UC-10** | **Просмотр всех заказов** | Доступ к полному реестру заказов всех пользователей для отчетности. | Администратор |
| **UC-11** | **Продажа билета через кассу** | Сценарий оформления билета сотрудником вокзала (без регистрации пассажира). | Кассир |
| **UC-12** | **Возврат билета** | Процедура отмены билета и возврата средств согласно правилам. | Пассажир, Кассир |
