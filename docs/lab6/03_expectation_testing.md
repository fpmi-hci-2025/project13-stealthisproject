# Этап 3. Тестирование ожиданий

## 1. Методика
Пользователям демонстрировались изолированные элементы интерфейса (скриншоты кнопок, иконок, форм) до совершения действия. Задавался вопрос: "Что произойдет, если вы нажмете сюда?". Ответы сравнивались с фактическим поведением системы.

## 2. Протокол тестирования

### Элемент 1: Иконка "Колокольчик" в шапке сайта
*   **Изображение:** Контурная иконка колокольчика с красной точкой.
*   **Вопрос:** "Что вы ожидаете увидеть при клике?"
*   **Ожидания пользователей:**
    *   "Уведомления об изменениях в расписании" (3/5)
    *   "Новости сервиса" (1/5)
    *   "Напоминание о поездке" (1/5)
*   **Фактическое поведение:** Открывается центр уведомлений (системные + по заказам).
*   **Вывод:** Соответствует ожиданиям.

### Элемент 2: Кнопка "Купить" в выдаче поиска
*   **Изображение:** Кнопка с ценой "от 25.00 BYN".
*   **Вопрос:** "Что произойдет после нажатия?"
*   **Ожидания пользователей:**
    *   "Сразу перейду к оплате" (2/5)
    *   "Перейду к выбору вагона/места" (3/5)
*   **Фактическое поведение:** Переход к выбору вагона и места.
*   **Вывод:** Часть пользователей может быть сбита с толку текстом "Купить".
*   **Рекомендация:** Заменить текст кнопки на "Выбрать место" или "Выбрать".

### Элемент 3: Ссылка на логотипе "Railway App"
*   **Изображение:** Логотип в левом верхнем углу на странице оформления заказа.
*   **Вопрос:** "Куда вы попадете при клике?"
*   **Ожидания пользователей:**
    *   "На главную страницу" (5/5)
*   **Фактическое поведение:** Переход на главную страницу (сброс процесса оформления).
*   **Вывод:** Ожидание верное, но действие деструктивное.
*   **Рекомендация:** Добавить предупреждение "Вы уверены, что хотите прервать оформление билета?", если пользователь кликает на логотип во время активного процесса покупки.

## 3. Общие выводы
Интерфейс в целом соответствует ментальным моделям пользователей. Критической ошибкой является возможная потеря данных при случайном уходе со страницы оформления заказа через логотип.
