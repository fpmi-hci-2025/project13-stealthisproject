## 2. Постановка задачи

### Описание проекта
Разработать систему электронных билетов для железнодорожного вокзала в Минске, включающую веб-приложение и мобильное приложение.

### Обязательные сценарии

Система должна поддерживать следующие сценарии:

1. **Покупка билета** - пассажир может купить билет онлайн с выбором конкретного места
2. **Поиск рейса по нескольким параметрам** - поиск с фильтрацией по времени, типу поезда, цене
3. **Проверка свободных мест** - визуализация схемы вагона с доступными местами
4. **Добавление нового рейса в базу данных** - администратор может добавлять рейсы
5. **Вывод информации о рейсе (включая остановки)** - детальная информация о маршруте
6. **Просмотр и обработка заказов пассажиров** - управление заказами для администраторов
7. **Регистрация нового пассажира** - создание учетной записи в системе

### Дополнительная функциональность

На основе анализа конкурентов выделены дополнительные функции:

- История поездок пользователя
- Сохранение данных пассажиров для быстрого оформления
- Электронные билеты с QR-кодами
- Push-уведомления о статусе заказа
- Календарь цен для выбора оптимальной даты
- Программа лояльности для частых пассажиров
- Возврат и обмен билетов онлайн
- Интеграция с различными способами оплаты (карты, ЕРИП, Apple Pay)

## 9. Объектная модель

Подробная объектная модель представлена в документе [object_model.md](object_model.md).

### Основные сущности

1. **User** - пользователь системы
2. **Passenger** - данные пассажира для билета
3. **Station** - железнодорожная станция
4. **Route** - маршрут следования
5. **IntermediateStop** - промежуточная остановка
6. **Train** - поезд на конкретную дату
7. **Carriage** - вагон в составе поезда
8. **Seat** - место в вагоне
9. **Order** - заказ пользователя
10. **Ticket** - электронный билет
11. **Payment** - платеж за заказ
12. **SearchQuery** - поисковый запрос

### Ключевые связи

- User → Passenger (1:N) - пользователь может сохранить несколько пассажиров
- User → Order (1:N) - пользователь создает заказы
- Route → Station (N:2) - маршрут связывает станции
- Train → Route (N:1) - поезд следует по маршруту
- Train → Carriage (1:N) - поезд состоит из вагонов
- Carriage → Seat (1:N) - вагон содержит места
- Order → Ticket (1:N) - заказ включает билеты
- Ticket → Seat (N:1) - билет резервирует место

## 11. Стратегия дизайна

### Общая концепция

**Философия:** Минимализм + функциональность  
**Принцип:** "Меньше кликов - больше результата"  
**Подход:** Mobile-first, адаптивный дизайн

### Дизайн для разных персонажей

#### Для Анны (частый пассажир)
- **Приоритет:** Скорость
- **Решение:** 
  - Сохраненные маршруты на главном экране
  - Автозаполнение данных
  - Оплата в один клик
  - Минимум шагов (цель: 3-4 экрана)

#### Для Владимира Ивановича (редкий пассажир)
- **Приоритет:** Понятность
- **Решение:**
  - Крупный шрифт (минимум 16px)
  - Подсказки на каждом шаге
  - Прогресс-бар оформления
  - Возможность распечатать билет

#### Для Ольги Сергеевны (кассир)
- **Приоритет:** Эффективность
- **Решение:**
  - Горячие клавиши
  - Быстрый поиск (автокомплит)
  - Минимум кликов
  - Четкая визуализация

#### Для Дмитрия Александровича (администратор)
- **Приоритет:** Контроль
- **Решение:**
  - Дашборд с аналитикой
  - Гибкие фильтры
  - Экспорт данных
  - Массовые операции

### Визуальный язык

**Цветовая палитра:**
- Основной: Синий (#0066CC) - доверие, надежность
- Акцент: Зеленый (#00AA44) - успех, доступность
- Предупреждение: Оранжевый (#FF9900)
- Ошибка: Красный (#DD0000)
- Фон: Светло-серый (#F5F5F5)

**Типографика:**
- Заголовки: Inter Bold, 24-32px
- Основной текст: Inter Regular, 16px
- Мелкий текст: Inter Regular, 14px

**Компоненты:**
- Кнопки: Скругленные углы (8px), тени
- Карточки: Белый фон, тонкая граница, тень
- Формы: Четкие лейблы, валидация в реальном времени

### Принципы взаимодействия

1. **Немедленная обратная связь**
   - Индикаторы загрузки
   - Анимации переходов
   - Уведомления об успехе/ошибке

2. **Предотвращение ошибок**
   - Валидация полей
   - Подтверждение критичных действий
   - Автосохранение

3. **Гибкость и эффективность**
   - Горячие клавиши для опытных
   - Подсказки для новичков
   - Персонализация интерфейса

4. **Эстетика и минимализм**
   - Только необходимая информация
   - Визуальная иерархия
   - Белое пространство

- NFR-1: Время загрузки страницы < 2 секунд

- NFR-7: Шифрование данных (HTTPS, TLS 1.3)
- NFR-8: Безопасное хранение паролей (bcrypt)

- NFR-11: Адаптивный дизайн (мобильные, планшеты, десктоп)
- NFR-12: Поддержка русского и белорусского языков
- NFR-13: Доступность (WCAG 2.1 уровень AA)

**Масштабируемость:**
- NFR-14: Горизонтальное масштабирование
- NFR-15: Кэширование часто запрашиваемых данных
